## 3. HTML Structure and Naming Conventions

### Section-based architecture

Every major page section must:
- Use a semantic `<section>` tag.
- Have a unique `id`.
- Have a unique section-level class.
- Use section-specific class names for its child elements.

Follow the BEM naming convention.

Example:

```html
<section id="hero" class="hero-section">
  <div class="hero-section__container">
    <h1 class="section-title hero-section__title">
      ...
    </h1>

    <p class="section-description hero-section__description">
      ...
    </p>

    <a href="#" class="button hero-section__button">
      ...
    </a>
  </div>
</section>
```

### Global reusable classes

For commonly repeated elements with similar styling, create reusable global classes.

Examples:
- `.container`
- `.button`
- `.section-title`
- `.section-subtitle`
- `.section-description`
- `.section-label`

Requirements:
- Reuse global classes wherever elements share the same design properties.
- Avoid unnecessary CSS duplication.
- When a global component needs section-specific customization, use CSS custom properties instead of duplicating its styles.
- Section-specific classes should handle unique layout and styling requirements.
- Avoid generic class names that may cause unintended style conflicts.

## 4. CSS Architecture and Organization

Create a separate `style.css` file.

**Important: CSS must be organized section by section, following the exact section class names used in the HTML.**

Follow this structure:

```css
/* ==========================================
   1. GLOBAL VARIABLES / DESIGN TOKENS
========================================== */

/* CSS variables */

/* ==========================================
   2. GLOBAL RESET & BASE STYLES
========================================== */

/* Reset, typography, body */

/* ==========================================
   3. GLOBAL REUSABLE COMPONENTS
========================================== */

/* Container, buttons, titles, descriptions */

/* ==========================================
   4. HEADER SECTION
========================================== */

/* Header styles */

/* ==========================================
   5. HERO SECTION
========================================== */

/* Hero styles */

/* ==========================================
   6. ABOUT SECTION
========================================== */

/* About styles */

/* ==========================================
   7. REMAINING SECTIONS
========================================== */

/* Continue based on the actual Figma section order */

/* ==========================================
   8. RESPONSIVE STYLES
========================================== */

/* Tablet */

/* Mobile */
```

### CSS organization rules

- Each section must have its own clearly separated CSS block.
- Mention the corresponding HTML section name in a comment before its styles.
- Keep section-specific styles grouped together.
- Do not scatter styles belonging to the same section across unrelated parts of the stylesheet.
- Keep global styles separate from section-specific styles.
- Avoid duplicate selectors and conflicting declarations.
- Maintain consistent formatting and indentation.
- Use meaningful CSS custom properties for reusable values.

### CSS Variables

Define centralized design tokens inside `:root`.

Include variables for:
- Primary, secondary, and accent colors.
- Background and text colors.
- Font families and font weights.
- Font sizes and line heights.
- Spacing values.
- Container widths.
- Border colors and radii.
- Shadows.
- Common button properties.

Example:

```css
:root {
  /* Colors */
  --color-primary: #000000;
  --color-secondary: #ffffff;
  --color-text-primary: #222222;
  --color-text-secondary: #666666;

  /* Typography */
  --font-primary: Arial, sans-serif;

  /* Layout */
  --container-width: 1440px;
  --section-spacing: 80px;

  /* Components */
  --button-radius: 8px;
}
```

These are examples only. Extract and use the actual values from Figma.

For section-specific customization of reusable elements, use CSS variables.

Example:

```css
.hero-section {
  --section-title-color: var(--color-primary);
  --section-button-background: var(--color-accent);
}
```

Do not hardcode repeated values unnecessarily.

## 5. Responsive Design

Currently, only the desktop Figma reference is available. Use the desktop design as the foundation for creating a basic, practical responsive layout.

The page must be compatible with:
- Large desktop screens.
- Standard desktop screens.
- Small desktop and laptop screens.
- Tablets.
- Mobile devices.

Requirements:
- Preserve the original desktop design as closely as possible.
- Use fluid layouts wherever appropriate.
- Use CSS Grid and Flexbox for adaptable layouts.
- Adjust typography, spacing, padding, and image dimensions based on viewport width.
- Stack columns vertically when required on smaller screens.
- Ensure images maintain their aspect ratios.
- Prevent overlapping content and text overflow.
- Maintain visual hierarchy and readability across screen sizes.
- Do not introduce unnecessary design elements or animations.

Use appropriate media queries and organize responsive styles clearly.

**Critical requirements:**
- No horizontal scrolling at any viewport width.
- No content extending beyond the viewport.
- No broken or overlapping layouts.
- The page must remain compatible across desktop, tablet, and mobile devices.

Since mobile and tablet references are unavailable, do not invent a completely different mobile design. Make only the responsive adjustments necessary to accommodate smaller screens.
